## 1. Findings

### Feasibility (FEAS)

- **FEAS-1** · MicroPython v1.29.0 `machine.I2S` on ESP32 is a thin shell over ESP-IDF `i2s_std` (the new channel driver): `i2s_new_channel`, `I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG`, `I2S_STD_CLK_DEFAULT_CONFIG(rate)`, MCLK unused, `auto_clear = true`. Standard Philips mode only. No PDM, no TDM, no LEDC, no APLL choice exposed. · E · MPY/ports/esp32/machine_i2s.c:361-399 · supports: the stock class can drive the DFR0954 (it needs only BCLK, LRC, DIN); PDM output and MCLK need a different driver.
- **FEAS-2** · Three I/O modes, chosen by how you call it. Blocking (default): `write()` blocks (`portMAX_DELAY`) until all bytes are in DMA. Non-blocking: `irq(handler)` makes a FreeRTOS task "i2s_non_blocking" (stack 2048 B, priority ESP_TASK_PRIO_MIN+1) that copies the app buffer to DMA, then calls `mp_sched_schedule(callback)`. asyncio: a `MP_STREAM_POLL` request switches `io_mode` to ASYNCIO and `write` uses delay 0 (partial write, returns bytes written). · E · MPY/ports/esp32/machine_i2s.c:42-43, 162-290, 442-466; MPY/extmod/machine_i2s.c:621-655 · supports: for mixed sound a Python mixer must produce every block in time in all three modes; the class only moves bytes. Nothing mixes, loops, or fades.
- **FEAS-3** · Buffer rules. `ibuf` is required (keyword, no default). DMA frame count per descriptor is fixed at 256 frames (`DMA_BUF_LEN_IN_I2S_FRAMES`); descriptor count = `ibuf / (256 * dma_frame_bytes)`, minimum 2. The app buffer is copied into DMA by `i2s_channel_write`, so there is one extra copy. 16-bit mono input is expanded to a stereo DMA frame (`get_dma_format`, line 134; the TX branch of that function and of `get_dma_bits` was not read in full). · E · MPY/ports/esp32/machine_i2s.c:45, 147-154, 356, 361-362 · supports: a DMA descriptor holds 256 frames; 256 / 16000 Hz = 16 ms, 256 / 32000 = 8 ms (calculated). So latency granularity from ibuf is a multiple of 8 to 16 ms; the exact ibuf for a sound-effect latency target is —.
- **FEAS-4** · Which core. MicroPython's task `mp_task` is pinned to core 1 (`MP_TASK_COREID` 1 unless `CONFIG_FREERTOS_UNICORE`), priority ESP_TASK_PRIO_MIN+1. The I2S non-blocking helper task is pinned to the same core (`MP_TASK_COREID`). · E · MPY/ports/esp32/mphalport.h:45-56, ports/esp32/main.c:80, 285; machine_i2s.c:449-456 · supports: the stock non-blocking mode shares core 1 with Python; it gives no second-core relief. An own C audio task could be pinned to core 0 with `xTaskCreatePinnedToCore`. Whether core 0 is free (the IDF system tasks, the SPI-LCD DMA interrupt allocation) is —; the SPI DMA interrupt core is decided where `spi_bus_initialize` is called. That call is at engine/driver/src/s3lcd.c:1494 (`SPI_DMA_CH_AUTO`, queue depth 10 at 1461/1501). The core of that call's caller is — (it runs in the MicroPython task, so core 1, H: it follows from the call site being a Python constructor).
- **FEAS-5** · The display send is queued DMA, not a busy loop. `show()` in "double" mode copies changed windows into an internal buffer, queues them, and returns; the next `show()` waits. The frame waits use FreeRTOS ticks. · E · ENG/engine/driver/src/frame.c:6-13, 185, 380-413; s3lcd.c:2633, 2691 · supports: the display DMA runs beside the CPU; an audio DMA runs beside it too. Whether both DMA channels plus PSRAM reads compete for the internal/PSRAM bus is —; no run has both. Bench figure: internal DMA largest free block 31,744 B while the scene runs (bench.md P595 A9, line ~290), a limit for DMA buffers: one 1 KB audio descriptor chain fits (calculated: 4 descriptors x 256 frames x 4 B = 4 KB).

I2S: Espressif's documents say the S3 I2Sn supports TDM and PDM TX modes, and the IDF I2S page says "ESP32 contains two I2S peripheral(s)" (the page is generic; the S3 count is — in this read, the MicroPython array `SOC_I2S_NUM` is used at machine_i2s.c:473 but its value was not read). - **FEAS-7** · CPU budget per frame, calculated. At the 40 ms frame (app.FRAME_MS = 40, ENG/games/app.py:26): samples per frame = rate x 0.040 = 640 (16 kHz), 1,280 (32 kHz), 1,764 (44.1 kHz), 1,920 (48 kHz). DMA byte rate for 16-bit stereo = rate x 4 = 64,000 / 128,000 / 176,400 / 192,000 B/s. Per sample per voice in Python, two inputs: 2 µs (H, a guess for a native/viper loop; no measurement exists) and 10 µs (H, derived from the measured 56.8 µs per particle update and 114 µs per spring body update, bench via engine council TL-8, as about 6 statements; the statement count is my estimate). One voice cost per frame: 16 kHz 1.28 / 6.4 ms; 32 kHz 2.56 / 12.8 ms; 44.1 kHz 3.53 / 17.6 ms. Against that: the headroom at 40 ms for Stack was 10.8 ms (engine council TL-9, calculated from run52), the fire's step+draw is 7.7 to 7.8 ms (bench.md P595, measured), the P656 smoke run is 20 to 25 fps (bench.md P656). · E for the frame and the references, H for the per-sample cost · supports: a naive bytecode mixer at 16 kHz mono with one voice costs 6.4 ms of the 10.8 ms headroom; two voices do not fit. A native-emitter loop is unmeasured, so it can only be settled by the spike in FEAS-15.
- **FEAS-8** · Python also adds GC pressure: floats are boxed; Python physics allocated 544 B per `Bodies.step` of 5 bodies (engine council TL-12). A naive mixer should use `array('h')` and `memoryview` with integer math to avoid boxing; whether `@micropython.viper` is built into this image is — (v1.29.0 default, H, not checked). `engine.nothing()` Python-to-C call is 2.60 µs and a C-to-Python call 5.34 µs (bench.md P589, measured), so the cost of a C mixer behind a per-frame call is under 10 µs of overhead (calculated: 2.6 + a few µs).

- **FEAS-10** · Where the layers go, in the engine's own style. The engine already splits `core/` (plain C99, no MicroPython header, Mac-tested with clang and ctypes), `binding.c` (the `engine` module with `Bodies`, `Balls`, `HeatField`), `micropython.cmake` (INTERFACE library) and a `driver/` submodule (s3lcd). · E · ENG/engine/README.md table; engine/micropython.cmake; build.sh:7-17 · supports: Candidate layout, three interfaces (all names are proposals; the decision is the PO's):

The game sees only the Mixer API. Output stays `machine.I2S` fed from the mixer's buffer.
  - **B, a sink and a source split.** `Sink` (writes blocks: `machine.I2S` today, an own C task later) and `Source` (a voice: sample player, noise, synth). Swap either. Costs more classes (against the PO's "small").

  The driver submodule (an own I2S task, DMA ring, underrun counter) exists only if FEAS-9's gaps matter. This follows D1/D2 (brief.md Frame, "Already decided").
- **FEAS-11** · How physics events feed sound. `event_t` is `{id, kind, speed}` with kinds `EVENT_HIT = 1`, `EVENT_SLEEP = 2`; the buffer holds `EVENTS_MAX = 64`, the rest only count in `dropped`; `events_drain` copies to an int array. - **FEAS-12** · The heat field has no read-back to Python. `HeatField` methods are `set_look, step, set_base, set_filter, burn, scroll, draw, __del__` (binding.c:334-341); there is no `read`/`sum`/`stats`. - **FEAS-13** · Sharing data with a C audio task while MicroPython runs. GC risk: MicroPython's heap moves nothing (non-moving mark-and-sweep), but a C task must not hold pointers into GC memory that Python may free; buffers must come from `heap_caps_malloc` (as `HeatField` does at binding.c:161-166) and be owned by a C object with a finaliser (the same pattern as `heat_field_make_new`, `mp_obj_malloc_with_finaliser`, binding.c:158). GC pauses block only the MicroPython task on core 1; an audio task on core 0 with its own DMA ring is not paused (H: FreeRTOS semantics; the ESP-IDF GC lock is not involved because the task does not touch the Python heap). Rule: Python writes parameters into a small struct of aligned 32-bit values (one writer); the audio task reads a snapshot (double buffer with a sequence counter) and never calls `mp_*`. The mixer's sample tables live in PSRAM or flash; PSRAM reads from an ISR/task are fine unless the flash cache is disabled during flash writes (H: the IDF doc, not searched), so any filesystem write while sound plays risks a gap — the audio DMA ring should hold at least the longest flash-write stall, which is —. · H (FreeRTOS and IDF knowledge) · supports: this is the rule to put to the decider and to test, not a proven fact.
