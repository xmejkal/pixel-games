# P755 part C: other sounds for later (wind, water, impacts, explosions, engines, whooshes)

Summary:
- Almost every sound here is noise plus a few resonant filters, driven by one game number. All are cheap on the S3 at 16 kHz. Only many-voice modal impacts need care, and the S3 SIMD helps there.
- Ready code with a clear license: STK (MIT-style, read) and DaisySP (MIT, read). Nemisindo is a paid product, not open code. The engine crate found is GPL-3.0.
- Cost classes are my own estimates from the model shapes, not measured. Only the license rows marked "read" were opened. Search was 11 calls, mostly snippets.

Notes:
- STK is MIT-style (Cook and Scavone). The condition is to keep the copyright notice. I read the LICENSE file.
- DaisySP is MIT and says closed-source and commercial use is fine. It has Dust, Particle noise, Modal Synthesis, Resonators, Granular Player. It is built for ARM microcontrollers, so the C is small and portable. I read the README list only, not the code.
- Shortcut from the libraries: rain, shakers and many drops are one PhISEM pattern. Random events, a decay, and a resonator. Reuse it for rain, sparks and embers.
- Shortcut for the rule we learned: impacts, explosions and whooshes are event sounds. Wind, rain bed, engine and stream stay smooth and follow a number.
- S3 use: a bank of 8 to 16 resonators is a good fit for the 128-bit SIMD and the esp-dsp biquad. Process the voices in one pass per 16 ms block.
- Farnell's book and the Pd files were not opened. I did not read the chapters for wind, engine or whoosh. A later session reads them first.
- The Nemisindo license and the Zong 2024 paper details are unconfirmed. Do not copy their code without asking them.
- Not found in 11 calls: Faust library details, Cook's PhISEM paper, any C code for wind or whoosh, and the full Minnaert formula text.
- Cost classes are unmeasured. The first task for each sound is to time one C render block against the 0.45 ms baseline.
